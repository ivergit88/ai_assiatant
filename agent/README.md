# Агент

Понимает запрос пользователя, вызывает MCP-тулы через GigaChat и формулирует ответ.
LLM подключена через [gpt2giga](https://github.com/ai-forever/gpt2giga): это прокси, который
делает GigaChat совместимым с OpenAI API, поэтому агент написан на обычной библиотеке `openai`.

## Запуск

```bash
cp .env.example .env   # заполнить GIGACHAT_CREDENTIALS и LLM_API_KEY
docker compose up --build
```

Агент: http://localhost:8002, документация: http://localhost:8002/docs.

Без Docker: поднять gpt2giga и MCP, затем `uv run uvicorn agent.main:app --port 8002`.

## Для бота (B): контракт

```
POST /v1/agent/message   {"user_id": "123", "text": "Напомни завтра в 10 позвонить Ивану"}
→ 200 {"reply_text": "...", "status": "done" | "need_clarification" | "error", "events": [...]}

POST /v1/agent/reset     {"user_id": "123"}   → 204, очищает историю диалога
```

- Ответ всегда 200, даже если GigaChat упал: тогда `status = "error"` и вежливый `reply_text`.
  Боту достаточно показать `reply_text`.
- `need_clarification` — агент задал вопрос («На какое время?»). Следующее сообщение
  пользователя просто отправляйте тем же запросом: агент помнит контекст.
- Голос: бот сначала распознаёт речь, потом отправляет текст сюда.
- Ответ может идти 5–20 секунд (GigaChat + тулы). Таймаут в боте — не меньше 60 секунд.
- Модели — `AgentRequest` / `AgentResponse` в `common/schemas.py`.

## Как устроен

```
бот ──HTTP──▶ agent/main.py ──▶ agent/core.py (цикл)
                                   │  ├─ prompt.py  — системный промпт с временем и календарём
                                   │  ├─ memory.py  — история в Redis
                                   │  └─ tools.py   — MCP ⇄ формат тулов OpenAI
                                   ├──▶ gpt2giga ──▶ GigaChat
                                   └──▶ MCP-сервер ──▶ PostgreSQL
```

Цикл на один запрос: LLM видит промпт, историю и тулы → просит вызвать тул → агент вызывает
его на MCP → отдаёт результат LLM → … → LLM пишет текстовый ответ. Максимум 6 раундов.

## Решения

- **Тулы берутся с MCP-сервера, а не описываются заново.** Единственный источник описаний —
  `mcp_server/server.py`. По дороге схема упрощается до подмножества JSON Schema, которое
  стабильно понимает GigaChat (без `anyOf`, `additionalProperties`).
- **`user_id` скрыт от модели.** Его нет в схеме тулов, агент подставляет его сам и
  перезаписывает, даже если модель прислала свой. Пользователь не может уговорить модель
  показать чужие задачи.
- **Уточнение — отдельный тул `ask_user`.** Явный сигнал надёжнее, чем угадывать по знаку
  вопроса. Бот получает `status = need_clarification`.
- **В промпте — календарь на 14 дней.** LLM плохо считает «в следующую среду»,
  а по готовой таблице «дата — день недели» почти не ошибается. Плюс правила по умолчанию:
  «утром» = 09:00, «в 3» = 15:00, срок без часа = 18:00.
- **Ошибки тулов возвращаются модели.** «Для встречи нужно указать время» — модель
  исправляется или спрашивает пользователя, а не падает.
- **В историю пишем только реплики, без вызовов тулов.** Обрезка списка не разрывает пары
  «вызов → результат», а к ответу ассистента дописывается скрытая сводка записей с id —
  чтобы «перенеси её на завтра» знало, о какой записи речь.
- **История — последние 10 реплик, TTL 7 дней** (`agent:ctx:{user_id}`). После ошибки
  обмен не сохраняется, повтор начинается с чистого листа.
- **Результаты тулов сжимаются** (без `user_id` и служебных дат) — меньше токенов, быстрее ответ.

## Тесты

`tests/test_agent.py`: скриптованная LLM + настоящие MCP, Postgres и Redis. Проверяют логику
вокруг модели: подстановку `user_id`, уточнения, ошибки тулов, историю, лимит шагов, HTTP.
Качество понимания запросов проверяется прогоном датасета E на настоящем GigaChat.

```bash
TEST_DATABASE_URL=... TEST_REDIS_URL=redis://localhost:6379/15 uv run pytest tests/test_agent.py
```

## Что улучшить

- Блокировка на пользователя, если бот пришлёт два сообщения подряд, не дождавшись ответа.
- Часовой пояс пользователя вместо одного на всех.
- Бонусные тулы `update_event` / `delete_event` / `complete_event`: агент подхватит их
  с MCP-сервера автоматически, менять код агента не нужно — только промпт.
